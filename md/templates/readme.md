## Customizing This Module

> [!IMPORTANT]
> Every generated file in this module is replaced when the module is regenerated (for example, on a provider upgrade).
> Put hand-written logic in **`{override_file}`**. IAC Foundry never creates, changes, or deletes that file, so your customizations carry forward to every new version.

### When to use `{override_file}`

- **Multi-source lookups** – an argument resolved from several module outputs, data sources, or locals
- **Non-`id` lookups** – an argument that needs `.object_id`, `.client_id`, `.versionless_secret_id`, etc.
- **Lifecycle rules** – `ignore_changes`, `prevent_destroy`, `create_before_destroy`

### How Terraform merges the override

| Content in `{override_file}` | Effect on `{resource_file}` |
| --- | --- |
| Top-level argument | Replaces only that argument |
| `lifecycle { }` | Merged argument by argument |
| Nested or `dynamic` block | Replaces **every** block of that type – copy the whole generated block, including its required arguments, then change it |
| `variable` block `type` | Replaces the whole type – copy the full generated type, then add your fields |

The override uses the same resource address as the generated file: `resource "{full_name}" "{resource_label}"`. Do not repeat `for_each`; it is inherited.
